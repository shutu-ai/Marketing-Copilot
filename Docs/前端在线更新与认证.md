# 前端在线更新与认证

本文档说明 Marketing Copilot 的「前端上传更新包在线更新」机制，以及其前置的
登录认证能力。该能力自 1.2.0 起提供，目标环境为 SLES 12 SP5 离线服务器。

## 1. 能力概览

- **登录认证**：多用户与角色（管理员 / 运营 / 只读），HMAC 签名令牌，登录后
  所有 `/api/*`（除 ready/health/login）都需要令牌。首次启动从环境变量
  （`MC_ADMIN_USERNAME` / `MC_ADMIN_PASSWORD`，默认 `admin / Huawei@123`）
  播种初始管理员，之后在「系统设置」→「用户与权限」中管理用户、角色与启停；
  修改自己的密码在右上角头像菜单中操作。
- **在线更新**：在「系统设置」→「系统更新」Tab 上传构建好的 tar.gz 离线更新包，服务端分片
  接收 → SHA-256 校验 → 安全解包 → 预检（路径安全、内层 checksums、必需文件、
  Python 语法、版本）→ 数据库备份 → 任务排空 → 停止旧服务 → 目录切换 →
  启动新版本 → 健康检查 → 失败自动回滚。
- **审计与历史**：登录、上传、校验、应用、回滚均写入 `audit_logs`；
  每次更新结果写入 `update_history`，页面可查看。

## 2. 前置条件（一次性）

### 2.1 systemd 托管部署

1. 服务单元需要 `KillMode=process`，否则 `systemctl stop` 会把更新执行器一并
   杀掉。新包中的 `deploy/marketing-copilot.service` 已包含该配置；已部署的
   服务器需手工执行一次：

   ```bash
   sudo sed -i '/^KillSignal=/a KillMode=process' /etc/systemd/system/marketing-copilot.service
   sudo systemctl daemon-reload
   ```

2. 让服务账户可以启停自己的单元（推荐，失败时会自动降级为 pid 方式停止 +
   直接启动）：

   ```bash
   sudo install -m 0644 /opt/marketing-copilot/payload/deploy/polkit-marketing-copilot.rules \
     /etc/polkit-1/rules.d/60-marketing-copilot.rules
   ```

   或手工创建 `/etc/polkit-1/rules.d/60-marketing-copilot.rules`，内容为允许
   `marketing-copilot` 用户管理 `marketing-copilot.service` 单元。

3. 确认 `/opt/marketing-copilot/data` 目录对服务账户可写（install.sh 已处理）。

### 2.2 手动/nohup 部署

无需 systemd 配置。`run.sh` 会自动创建 `$APP_HOME/updates` 并导出
`MC_STATE_DIR`、`MC_UPDATE_DIR`、`MC_UPDATE_MODE=manual`。

如需把手动部署转为 systemd 托管的后台服务，可直接用后端自带的安装脚本
创建单元（自动复用 `run.sh` 与环境文件，设置 `KillMode=process`，安装
polkit 规则并把 `MC_UPDATE_MODE` 切换为 `systemd`）：

```bash
cd /opt/marketing-copilot-manual/backend
sudo /opt/marketing-copilot-manual/venv/bin/python -m tools.install_systemd_service
```

`run.sh` 启动时也会自动检查：对应 systemd 单元不存在且以 root 执行时，会
按应用目录属主创建单元（不启动、不启用）；`MC_SKIP_SYSTEMD_CHECK=1` 可跳过。
单元创建后，后续应用更新即走 systemd 模式（`systemctl stop/start`）。

## 3. 配置项

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `MC_AUTH_DISABLED` | `0` | `1` 时关闭认证，仅限开发/自动化测试 |
| `MC_ADMIN_USERNAME` | `admin` | 首次启动播种的管理员账号（之后在用户与权限中管理） |
| `MC_ADMIN_PASSWORD` | `Huawei@123` | 首次启动播种的管理员密码，生产必须修改 |
| `MC_AUTH_SECRET` | 空 | 令牌签名密钥；留空自动生成并持久化到 `$MC_STATE_DIR/auth_secret` |
| `MC_AUTH_TOKEN_TTL_HOURS` | `12` | 令牌有效期 |
| `MC_UPDATE_MODE` | 自动探测 | `systemd` 或 `manual` |
| `MC_STATE_DIR` | `backend/data` | 状态目录（auth_secret、更新状态） |
| `MC_UPDATE_DIR` | `$MC_STATE_DIR/updates` | 更新暂存/备份/日志目录 |
| `MC_UPDATE_MAX_TOTAL_BYTES` | 2 GiB | 单包最大字节数 |
| `MC_UPDATE_MAX_CHUNK_BYTES` | 64 MiB | 单个分片最大字节数 |
| `MC_UPDATE_HEALTH_TRIES` | `180` | 健康检查重试次数 |
| `MC_UPDATE_HEALTH_INTERVAL` | `2` | 健康检查间隔（秒） |
| `MC_UPDATE_KEEP_BACKUPS` | `3` | 保留最近 N 份代码备份 |
| `MC_UPDATE_KEEP_UPLOADS` | `3` | 保留最近 N 份已校验的更新包（应用中的除外），更早的自动清理 |

## 4. 更新包要求

使用仓库内构建脚本生成（已内置版本元数据）：

```bash
# 手动部署包（system Python 3.11.5）
bash deploy/build-sles12sp5-system-python-manual.sh --output release
```

包结构必须包含：

```text
backend/                 # 后端源码（含 release.json）
frontend/dist/           # 前端构建产物
offline/wheels/          # 离线 wheel（可缺省：表示不更新依赖）
offline/requirements.txt
checksums.sha256
```

校验逻辑：外层 SHA-256（前端提供时）→ 安全解包（拒绝绝对路径/`..`/符号链接）
→ `checksums.sha256 -c` → 必需文件检查 → `compile()` 全量语法检查 →
版本比较。任何一步失败都不会进入应用阶段。

## 5. 操作流程

1. 登录后进入「系统设置」→「系统更新」Tab。
2. 拖入更新包，点击「上传并校验」，等待校验报告。
3. 若存在进行中的营销活动，页面会提示；确认维护窗口后勾选「强制应用」。
4. 点击「应用更新」并确认。系统将：备份数据库 → 把 `sending` 任务重新排队 →
   停止调度/发送 → 备份旧代码 → 停止服务 → 切换目录 →（依赖变更时）离线安装
   wheel → 启动 → 健康检查（`/api/ready`）→ 成功记录历史。
5. 若健康检查失败，执行器自动回滚到旧版本并再次健康检查。
6. 需要人工回滚时，点击「回滚」，恢复最近一次备份。

更新期间页面会轮询状态；服务重启的几十秒内请求失败属正常，页面会静默重试。

## 6. 安全边界与说明

- 在线更新只覆盖**应用层**（backend/frontend/offline wheels）。Python/OpenSSL
  运行时、systemd 单元、`/etc/marketing-copilot.env` 的变更仍走 install.sh 和
  运维流程。
- **更新不会覆盖配置与业务数据**：
  - 数据库文件（`DUCKDB_PATH` 指向）、日志、备份、更新暂存目录都在
    `backend` 目录之外，切换目录不触及；
  - `backend` 目录内的运行期条目——`db_config.json`（页面保存的数据库路径）、
    `uploads`（活动名单/输出目录）、`monitor_dir`、`data`（认证密钥等）、
    `logs`、数据库文件——在切换时会被**保留**，只替换代码文件；
  - 环境文件（`/etc/marketing-copilot.env` 或
    `$APP_HOME/marketing-copilot.env`）位于 `backend` 之外，不会被覆盖。
- 更新执行器以服务账户运行；systemd 部署建议安装 polkit 规则以正常使用
  `systemctl start/stop`，缺失时自动降级为 pid 停止 + 直接启动。
- 每次应用前强制备份数据库（复用 `tools.backup_database`），代码备份保留
  `MC_UPDATE_KEEP_BACKUPS` 份，已校验的更新包自动保留最近
  `MC_UPDATE_KEEP_UPLOADS` 份（未完成的临时上传超 24 小时清理），无需手工清理。
- 上传接口已纳入认证与审计；包未签名时请通过受控介质分发，避免中间人替换。
- 多机部署需逐机上传应用，本功能为单机更新机制。

## 7. 故障排查

- 状态停在 `stopping`：查看 `$MC_UPDATE_DIR/logs/runner-*.log`。
- 更新后服务未启动：检查 `journalctl -u marketing-copilot.service`；执行器日志
  中会写明降级路径（pid 停止 / 直接启动）。
- 健康检查持续失败：执行器应已回滚；若未回滚，手工执行
  `sudo systemctl restart marketing-copilot.service` 并核对
  `/opt/marketing-copilot/backend` 下文件版本。
- 令牌失效：`MC_AUTH_SECRET` 变化或 `$MC_STATE_DIR/auth_secret` 丢失，重新登录
  即可。
