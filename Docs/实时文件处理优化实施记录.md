# 实时文件处理优化实施记录

## 实施范围

本次实现覆盖实时白名单版本化、异步摄取、文件级租约、分块进度、失败分类与退避、监控指标、人工重试/归档，以及 SLES12SP5 手工部署包构建。

关键入口：

- `backend/services/realtime_whitelist_service.py`：白名单源文件 hash、版本、持久化 DuckDB 索引、原子 active 切换、历史活动迁移和延迟清理。
- `backend/services/realtime_ingestion_worker.py`：单并发实时文件 Worker、租约恢复、白名单构建和有限重试。
- `backend/services/realtime_ingestion_retry_service.py`：错误分类和退避策略。
- `backend/services/ingestion_job_service.py`：文件/分块状态、租约、进度和重试字段。
- `backend/services/realtime_campaign_service.py`：监听目录轻量同步、队列登记和持久索引匹配。
- `frontend/src/views/monitor/FileMonitor.vue`：阶段、进度、错误、批量重试和归档。

## 运维恢复要点

```bash
# 查看实时文件队列、阶段、租约和错误
curl --fail http://127.0.0.1:${MC_PORT:-19090}/api/monitor/realtime

# 触发单文件人工重试（只允许 failed/quarantined/retrying）
curl -X POST http://127.0.0.1:${MC_PORT:-19090}/api/monitor/realtime/files/<file_id>/retry

# 查看 Prometheus 指标
curl --fail http://127.0.0.1:${MC_PORT:-19090}/metrics | grep realtime_

# SLES 服务恢复后检查
systemctl status marketing-copilot --no-pager
journalctl -u marketing-copilot -n 100 --no-pager
curl --fail http://127.0.0.1:${MC_PORT:-19090}/api/ready
```

白名单构建失败不会切换 active 版本；正在处理的文件通过 `whitelist_version_id` 继续使用绑定版本。若 active 索引在读取时损坏，系统会记录 `WHITELIST_INDEX_ROLLBACK`，标记损坏版本为 failed，回退到最近可用 ready 版本并更新当前文件绑定；无可用回退版本时给出不可重试的诊断错误。旧版本只有在没有非终态绑定文件后才会退役，并在保留窗口结束后删除索引和源文件。
