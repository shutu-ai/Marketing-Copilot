# Marketing Copilot 项目现状分析

## 1. 总体结论

当前项目已经形成一套可操作的 Vue 3 + FastAPI 管理系统原型，UI 页面、后端 API、DuckDB 数据模型和多数配置类 CRUD 基本齐全。

但目前项目更接近“营销活动管理与流程演示平台”，还不是可以替代旧脚本的生产短信发送系统。最关键的两个缺口是：

1. SMPP 实际发送仍是模拟实现；
2. 批量活动和实时活动只完成名单处理与结果记录，没有真正触发短信发送。

因此，当前项目可以管理配置、上传文件、筛选用户和查看统计，但“文件进入 → 满足规则 → 真实发送 → 接收回执 → 可追踪重试”的主业务闭环尚未完成。

## 2. 当前技术架构

```text
Vue 3 + TypeScript + Element Plus
                ↓ Axios /api
FastAPI Router
                ↓
Service 业务层
                ↓
DuckDB + 本地文件目录
                ↓
RabbitMQ（可选）
                ↓
短信发送服务（当前为模拟桩）
```

### 5.1 批次处理的实际行为

当前 `process_batch()` 会：

1. 读取客户名单；
2. 截取当前批次范围；
3. 识别 `msisdn` 字段；
4. 排除当天已经处理的号码；
5. 将号码写入活动目录下的 `output/YYYYMMDD.csv`；
6. 将批次状态标记为 `sent`；
7. 更新每日发送统计。

该方法没有调用：

- RabbitMQ 发布；
- `sms_sender.process_message()`；
- SMPP 发送；
- 短信模板渲染。

所以这里的 `sent` 实际表示“写入输出文件并完成统计”，不代表短信真实发送成功。

代码还限制同一活动每天只能处理一个已经标记为 `sent` 的批次。生成多个批次后，每天可能只能执行一批，需要确认是否符合业务规则。

## 6. 实时营销活动实现情况

实时活动支持：

- 创建、编辑、复制和删除；
- 配置活动时间及每日发送时间；
- 上传活动专属白名单；
- 手动上传实时事件文件；
- 对事件文件和白名单进行手机号交集匹配；
- 保存收到的文件；
- 将匹配手机号写入每日输出文件；
- 统计文件数、事件用户数和匹配用户数。

### 6.1 实时处理的实际行为

当前 `receive_file()` 执行：

```text
上传事件文件
  → 提取并去重手机号
  → 读取活动白名单
  → 计算手机号交集
  → 保存原始文件
  → 将匹配手机号写入 output/YYYYMMDD.csv
  → 保存文件统计
```

它没有：

- 检查活动是否处于有效日期范围；
- 检查当前星期和发送时间段；
- 读取并渲染短信模板；
- 发布到 RabbitMQ；
- 调用 SMPP；
- 应用全局排除名单；
- 防止同一用户当天重复发送。

因此，目前实现的是“实时名单匹配”，不是完整的“实时短信营销”。

## 7. 实际短信发送链路

设计上的发送链路为：

```text
监控文件
  → RabbitMQ publish
  → campaign.{campaign_name}
  → RabbitMQ consumer
  → 白名单检查
  → 查找短信内容活动
  → 根据用户语言选择模板
  → 替换模板变量
  → SMPP 发送
  → 写入 sms_log
```

RabbitMQ、白名单查询、模板选择和日志记录已经编码实现。

但真正发送短信的 `_send_sms_via_smpp()` 目前是模拟桩。当前行为只是记录类似以下日志并返回成功：

```text
[SMPP SEND] ...
```

没有 SMPP 配置时，也会模拟发送并返回成功。

后端依赖文件中没有 `smpplib`，说明当前项目尚未接入旧脚本的实际 SMPP 能力。

这会导致 `sms_log.status = sent` 目前只能表示模拟发送流程完成，不能表示短信已经提交到 SMSC 或成功投递。

## 10. 安全与生产化问题

当前项目尚未实现：

- 登录认证；
- 用户角色和权限；
- API 访问令牌；
- 配置密码加密；
- SMPP/RabbitMQ 密码脱敏返回；
- 操作审计；
- API 限流；
- 发送频控；
- 黑名单和退订管理；
- SQL 查询权限隔离；
- 文件路径访问范围限制；
- CORS 来源限制。

文件监控和活动目录允许从 UI 输入路径，后端缺少严格的允许目录校验，可能读取、移动或删除非预期位置的文件。

## 12. 建议优先打通的业务闭环

下一阶段最优先的工作不是继续增加页面，而是完成一条可靠的端到端业务链路：

```text
活动启用
 → 自动监听或接收文件
 → 校验活动日期和发送时段
 → 去重、白名单、排除名单
 → 选择语言模板
 → 创建持久化发送任务
 → SMPP 真实发送
 → 接收状态报告
 → 重试和失败归档
 → UI 实时展示状态
```

在该链路完成后，再逐步补充权限管理、审计、告警、限流、自动化测试和部署能力。
