# Marketing Copilot 角色权限矩阵

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 文档状态 | 已确认基线，进入实施 |
| 适用系统 | Marketing Copilot |
| 编制日期 | 2026-09-09 |
| 适用角色 | 管理、营销、分析 |
| 权限原则 | 前端可见性控制与后端接口鉴权同时生效 |

本文档用于统一角色定义、功能权限、接口权限和后续验收口径。除已明确指定的权限外，其余权限依据角色名称和功能职责进行匹配。

## 2. 角色定义

| 展示名称 | 建议内部值 | 职责定位 |
|---|---|---|
| 管理 | `admin` | 系统配置、用户权限、更新、数据库和全部业务功能管理 |
| 营销 | `marketing` | 营销活动、短信内容、发送运营和失败处理 |
| 分析 | `analyst` | Dashboard、监控、报表和运营数据只读分析 |

### 2.1 旧角色迁移建议

当前系统角色为 `admin / operator / viewer`，建议迁移如下：

| 旧角色 | 新角色 | 说明 |
|---|---|---|
| `admin` | `admin` | 保持不变 |
| `operator` | `marketing` | 运营操作能力迁移为营销业务操作能力 |
| `viewer` | `analyst` | 保留只读能力，定位为分析角色 |

该映射已确认，实施时迁移已有用户角色并保留审计记录。

## 3. 权限标识

| 标识 | 含义 |
|---|---|
| `R` | 只读查看，包括列表、详情、统计和报表 |
| `RW` | 查看及操作，包括新增、修改、删除、启动、暂停、重试等 |

| `隐藏` | 不显示左侧导航入口；是否保留直接路由由后端权限决定 |

## 6. 明确需求与实现口径

### 6.1 Database Query

“左侧栏隐藏”按所有角色隐藏处理。建议保留路由和后端能力，但后端接口必须继续限制为管理角色，避免仅通过隐藏菜单实现权限控制。

### 6.2 设置页

以下五个设置页仅管理角色可见且可访问：

- General
- SMPP
- Database
- System Update
- User & Roles

Logs 不在明确限制清单内，本矩阵暂按所有已登录角色只读处理。

### 6.3 `accepted` 纳入 Delivered 统计

短信中心配置为不要求等待回执时：

- `required`：只有收到有效 DLR，例如 `DELIVRD`，才计入 Delivered；
- `optional` / `disabled`：SMSC 接受提交后，任务状态为 `accepted`，立即计入 Delivered 统计；
- 原始任务状态建议继续保留为 `accepted`，用于审计和区分“短信中心已接受”与“终端已送达”。

该口径应统一应用于短信任务统计、Dashboard、活动详情、批次 `delivered_count`、日报、失败率和 Delivered KPI。

## 8. 实施要求

1. 后端统一定义角色常量和角色权限矩阵，避免散落的字符串判断。
2. 前端菜单、路由和页面操作按钮使用同一份权限能力模型。
3. `/api/settings`、`/api/smpp`、`/api/db-config` 等系统配置接口增加管理角色鉴权。
4. 角色迁移时将已有 `operator`、`viewer` 用户转换为新角色，并保留审计记录。
5. 登录后和页面刷新后都应从服务端恢复真实角色，不能将默认 `admin` 作为持久权限来源。
6. `accepted` 统计改造必须保持原始状态可追溯，并覆盖历史数据、批量任务和多段短信场景。

## 9. 验收测试基线

### 9.1 权限测试

- 管理角色可以访问全部业务功能和五个受限设置页。
- 营销角色可以维护营销活动、短信模板和发送运营，但不能访问系统配置。
- 分析角色可以查看 Dashboard、监控、任务和报表，但不能改变业务状态。
- 三类角色左侧栏均不显示 Database Query。
- 营销和分析角色直接调用受限配置 API 时返回 `403`。
- 所有角色均可修改本人密码。

### 9.2 Delivered 统计测试

- required 模式：无 DLR 时不计入 Delivered。
- required 模式：收到 `DELIVRD` 后计入 Delivered。
- optional 模式：状态为 `accepted` 后计入 Delivered。
- disabled 模式：状态为 `accepted` 后计入 Delivered。
- Dashboard、短信任务统计、活动详情和批次统计结果一致。
- 多段短信按一个任务计数，不按多个 message id 重复计数。

## 10. 已确认决策

1. `Logs` 按所有已登录角色只读处理。
2. 分析角色允许查看手机号、排除名单和短信正文。
3. 营销角色允许执行活动取消、失败任务归档和手工确认送达。
4. Database Query 对所有角色隐藏左侧入口，管理角色保留受控后端访问。
5. `accepted` 在界面上继续显示原始状态 `accepted`，仅在 Delivered 统计中纳入。
