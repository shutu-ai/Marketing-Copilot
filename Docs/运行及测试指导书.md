# Marketing Copilot 手动测试指导书

## 1. 使用范围与通过标准

本指导书用于在浏览器中手动验证 Marketing Copilot 的主要功能。除选择随包提供的 CSV 文件和点击界面控件外，所有文字、号码、模板和 SQL 均可直接从本文复制粘贴，无需自行编写测试数据。

测试数据目录：`manual-test-assets`。

> 安全提示：测试号码为虚构号码。正式 SMSC 环境下不要执行本指导书；应使用本地 SMSC 模拟器或经客户确认的测试 SMSC。不要修改“数据库配置”中的数据库路径，否则会切换业务数据库。

总通过条件：批量活动最终产生 5 条 `delivered`；实时活动最终产生 3 条 `delivered`；两类活动合计 8 条 `delivered`。批量活动仅排除 `251900001005`；实时活动只向活动白名单中的号码创建任务。

记录规则：每完成一项，在标题前记录“通过/失败”；实际结果与预期完全一致才算通过。若状态仍为 `queued/submitted`，先等待 30 秒并刷新；仍未变为 `delivered` 才判失败，并记录页面错误。

## 2. 测试前准备

本地开发测试需要分别启动后端、前端和 SMSC 模拟器。以下命令均假定当前 PowerShell 已打开在解压后的项目根目录（即能看到 `0.首次安装依赖.ps1` 的目录）。请在文件资源管理器中打开该目录，在地址栏输入 `powershell` 后按回车；无需使用固定的磁盘路径。

### 2.1 首次安装依赖

仅第一次运行或依赖变化时执行：

先确认已安装 64 位 Python 3.13 和 Node.js。在项目根目录复制执行：

```powershell
.\0.首次安装依赖.ps1
```

预期：所有命令均正常结束，没有红色错误。执行下面命令应显示 Python 3.13、pandas 2.3.3，并输出 `smpplib OK`：

```powershell
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -c "import pandas, smpplib; print('pandas', pandas.__version__); print('smpplib OK')"
```

若提示 `No suitable Python runtime found`，说明尚未安装 Python 3.13；先安装 64 位 Python 3.13，再重新执行。不要用 Python 3.14 创建本项目环境。已成功创建 `.venv` 时无需重复创建，但依赖文件变化后应重新执行安装依赖命令。

### 2.2 启动后端

打开第 1 个 PowerShell 窗口：

```powershell
.\2.启动后台.ps1
```

预期：出现 `Application startup complete` 和 `Uvicorn running on http://0.0.0.0:8000`。后端地址为 `http://127.0.0.1:8000`，用于 API 和健康检查。

### 2.3 启动前端

打开第 2 个 PowerShell 窗口：

```powershell
.\1.启动前台.ps1
```

预期：显示 `Local: http://localhost:5173/`。前端地址为 `http://localhost:5173`，这是浏览器操作页面的地址；开发服务器会将 `/api` 转发到 `http://localhost:8000`。

### 2.4 启动本地 SMSC 模拟器

打开第 3 个 PowerShell 窗口，复制粘贴：

```powershell
.\3.启动SMSC模拟.ps1
```

预期：窗口保持运行且没有退出。整个发送测试期间不要关闭此窗口。若客户环境不是该路径，仅替换第一行路径。

保持模拟器窗口运行，再打开一个 PowerShell 窗口执行 SMPP 冒烟测试：

```powershell
Set-Location .\backend
..\.venv\Scripts\python.exe -m tools.smsc_smoke_test --host 127.0.0.1 --port 2775 --system-id test --password test --source telebirr --destination 251900001240 --message "Marketing Copilot local SMPP test"
```

预期输出包含 `submit_sm_resp`、`delivery_receipt` 和 `PASS: submit_sm_resp and DELIVRD receipt received`。若提示 `No module named smpplib`，说明使用了全局 Python；应确认命令开头是 `..\.venv\Scripts\python.exe`，并重新执行第 2.1 节依赖安装。

### 2.5 打开系统并检查健康状态

本地开发测试时，浏览器打开前端地址 `http://localhost:5173`。健康检查使用后端地址，另开 PowerShell 执行：

```powershell
Invoke-RestMethod 'http://127.0.0.1:8000/api/ready'
Invoke-RestMethod 'http://127.0.0.1:8000/api/health'
```

预期：`ready` 返回 `status = ready`；`health` 返回 `status = ok`、`database = connected`。前端首页能打开并显示统计卡片。

管理界面已启用登录认证：首次打开页面会跳转到登录页，默认账号为
`admin / Huawei@123`（生产环境请通过 `MC_ADMIN_PASSWORD` 修改后重新部署）。
登录后可进入“系统设置”→“系统更新”Tab 完成应用层在线升级（上传、校验、应用与回滚），
详见 `Docs/前端在线更新与认证.md`。运行自动化测试（Playwright）时，可用
`MC_AUTH_DISABLED=1` 启动后端以绕过登录校验。

若使用已经部署好的服务器，前后端通常由同一个部署地址提供，例如 `http://192.168.1.20:8000`：浏览器直接打开该地址，健康检查访问 `<部署地址>/api/ready` 和 `<部署地址>/api/health`。这要求服务器已有 `frontend/dist`；后端会同时提供静态页面。若使用 Nginx 或其他网关，则以实施人员提供的前端地址和后端 API 地址为准。

### 2.6 系统设置

进入“系统设置”→“基础设置”，将“系统模式”选择为“生产模式”，点击“保存”。批量活动基础目录和实时活动基础目录保持现有值不改。

预期：提示“保存成功”。本地模拟器只有在生产模式下才会收到真实 SMPP 提交。

| 字段 | 值 |

| Port | `2775` |
| System ID | `test` |
| Password | `test` |
| Source Address | `telebirr` |
| Bind Type | `transceiver` |
| Data Coding | `0 - GSM 7-bit` |
| TON / NPI | `0` / `0` |
| 连接池 | `1` |

保存后点击“测试连接”。若已有启用的生产 SMSC，请先由管理员停用，确保测试配置是第一条启用配置。

预期：列表出现 `Manual Test SMSC`，状态为启用；连接测试提示“连接测试成功”；模拟器窗口出现 bind 日志。

### 4.4 启动和判定结果

点击“开始”。等待 30 秒，进入“短信任务”，活动类型选择“批量”，刷新。

预期必须同时满足：

- `MANUAL_BATCH_001` 恰好有 5 条任务，最终状态均为 `delivered`；
- 号码为 `251900001001`、`251900001002`、`251900001003`、`251900001004`、`251900009999`，每个一次；
- 不存在 `251900001005`（排除）的任务；重复的 `251900001001` 没有产生第二条任务；
- 语言分别为 English、Amharic、Tigrigna、Somali；
- 内容中的 `{event_filter_id}` 等花括号变量已替换，例如第一条包含 `BATCH_EVT_001`、`CELL_A01`、`251900001001`、`OFFER10`；
- 每条任务“尝试”大于等于 1，且 SMSC 模拟器窗口能看到 4 次提交和回执日志。

打开批量活动详情。预期：共 4 个批次；批次大小为 2；送达用户为 5。批次最终状态允许包含 `sent` 和最后一个不足批次的 `skipped`，不得存在长期 `pending/processing/failed`。

## 6. 查询、监控与运维功能

### 6.1 数据库查询（只读）

进入“数据库查询”。页面顶部默认显示“SQL 查询”编辑器；若被关闭，可点击右上方“SQL 查询”重新打开。将以下只读 SQL 逐条复制到编辑器执行：

```sql
SELECT campaign_type, status, COUNT(*) AS task_count
FROM sms_tasks
WHERE campaign_name IN ('MANUAL_BATCH_001', 'MANUAL_REALTIME_001')
GROUP BY campaign_type, status
ORDER BY campaign_type, status;
```

预期：`batch / delivered / 5` 和 `realtime / delivered / 3`。

```sql
SELECT msisdn, COUNT(*) AS task_count
FROM sms_tasks
WHERE campaign_name IN ('MANUAL_BATCH_001', 'MANUAL_REALTIME_001')
GROUP BY msisdn
ORDER BY msisdn;
```

预期：`251900001001`、`...1002`、`...1003` 各 2 条，`251900001004` 为 1 条；没有其他号码。

```sql
SELECT COUNT(*) AS unrendered_count
FROM sms_tasks
WHERE campaign_name IN ('MANUAL_BATCH_001', 'MANUAL_REALTIME_001')
  AND content LIKE '%{%';
```

预期：`unrendered_count = 0`。只执行本文 `SELECT`，不要粘贴任何 `UPDATE/DELETE/DROP`。

### 6.2 仪表盘与容量中心

进入“仪表盘”并刷新。预期：页面无报错，任务统计不小于本次测试产生的 7 条。

进入“容量中心”→“刷新”。预期：运行 Worker 大于等于 1，启用 SMSC 大于等于 1；SMSC 列表中 `Manual Test SMSC` 显示健康。点击“立即评估告警”，预期操作完成且页面不报错。

### 6.3 运维中心

进入“运维中心”：

1. “活动与进度”中能找到两个 `MANUAL_` 活动，任务进度与上述数量一致。
2. “异常中心”点击“检查配置并记录异常”。预期：SMPP、Worker、目录等检查为正常；若有异常，记录代码和说明即判该检查失败。
3. “DLR 映射”应显示状态码、任务状态及是否可重试，表格非空。
4. “审计与报表”中应存在本次新增、启动等操作记录。依次点击可用的导出按钮；浏览器应下载 CSV，且文件可打开、有表头。

“失败处理”和“重新入队”只有存在失败任务时才能完整验证。本次成功链路预期失败列表为空；不要为了制造失败而连接真实错误地址。若客户测试环境预置了 `failed/expired` 任务，可选择一条点击“重新入队”，预期提示成功并变为 `queued/retrying`。

### 6.4 数据监控、RabbitMQ 与数据库配置

- “数据监控”：页面能打开并显示已有配置。目录监控依赖客户预先提供的安全测试目录；无授权时只验证加载和刷新，不新增、不删除服务器目录配置。
- “RabbitMQ”：属于可选入口。若客户已提供测试 RabbitMQ，点击已有配置的连接测试并应成功；未提供时记录“环境不适用”，不判产品失败。
- “系统设置”→“数据库配置”：点击“测试”，预期当前数据库连接成功；**不要修改路径，不要点击保存新路径**。
