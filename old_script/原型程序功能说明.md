# 原型程序功能说明

## 1. 程序概述

`market_template_marketing_thread.py` 是一个常驻运行的短信营销发送程序。程序监听指定目录中新创建的 CSV 文件，对其中的用户数据进行去重、白名单过滤和排除名单过滤，再根据营销活动配置生成短信内容，并通过 SMPP 长连接将短信逐条发送到 SMSC。

程序的主要能力包括：

- 递归监听目录中新创建的 CSV 文件；
- 限制短信任务的有效时间为工作日 08:30～17:30；
- 按活动 ID 和手机号去重；
- 使用白名单控制允许发送的用户；
- 使用排除名单过滤禁止发送的用户；
- 根据活动配置选择短信模板；
- 可选按基站区域匹配不同语言的短信模板；
- 使用内存队列将文件处理与短信发送解耦；
- 通过 SMPP 长连接发送短信；
- 连接断开时自动重连并重试；
- 保存短信提交记录和配置匹配错误记录。

## 2. 总体处理流程

```text
程序启动
  ↓
初始化日志、工作目录、活动配置和白名单
  ↓
连接 SMSC 并绑定 transceiver
  ↓
启动短信发送线程
  ↓
递归监听当前目录中新创建的 CSV 文件
  ↓
解析文件名中的任务时间
  ↓
判断是否为工作日 08:30～17:30
  ↓
读取 CSV，提取活动 ID、手机号和基站 ID
  ↓
数据去重 → 白名单过滤 → 排除名单过滤
  ↓
根据活动 ID 和语言读取短信模板
  ↓
将短信发送请求写入内存队列
  ↓
删除原始 CSV 文件
  ↓
发送线程从队列中逐条取出请求
  ↓
通过 SMPP 发送短信并记录提交日志
```

## 3. 程序组成

### 3.1 全局短信队列

程序通过 `Queue` 创建全局队列 `sms_queue`，用于保存待发送短信请求。

每条队列数据的结构为：

```python
(msisdn, message, event_filter_id, cell_id)
```

对应含义如下：

| 字段 | 说明 |
| --- | --- |
| `msisdn` | 用户手机号，不包含程序追加的国家码 |
| `message` | 最终短信内容 |
| `event_filter_id` | 营销活动或事件过滤器 ID |
| `cell_id` | 用户对应的基站或区域标识 |

### 3.2 `SMSCConnection`

该类负责管理 SMPP 连接和短信发送，主要包含以下方法：

- `connect()`：连接 SMSC，并以 transceiver 模式绑定；连接失败时每隔 5 秒重试一次，直到成功。
- `disconnect()`：执行解绑并断开连接。
- `send_sms()`：编码、拆分并发送短信；连接中断时重新连接并再次发送。

### 3.3 `FileEventHandler`

该类继承 `FileSystemEventHandler`，负责处理新创建文件事件。只有以 `.csv` 结尾的新文件才会进入业务处理流程。

### 3.4 `DirMonitor`

该类封装 `watchdog.Observer`，递归监听指定目录及其子目录。

### 3.5 `sms_worker()`

短信工作线程持续从 `sms_queue` 中获取任务，并调用 `SMSCConnection.send_sms()` 串行发送。

当队列中收到 `None` 时，工作线程结束。

## 4. 启动流程

程序入口位于：

```python
if __name__ == "__main__":
```

启动过程如下：

1. 初始化日志，日志写入当前工作目录下的 `run.log`；
2. 设置语言控制开关 `switch_lan`；
3. 创建 `sms_finished` 和 `id_error` 目录；
4. 创建 `id_error/id_error_list.csv`；
5. 读取 `../campaign_configuration.ini`；
6. 读取 `whitelist/whitelist.csv` 并将手机号保存为集合；
7. 创建并连接 SMSC；
8. 启动短信发送线程；
9. 递归监听当前目录 `.`；
10. 主线程进入无限循环，直到收到 `Ctrl+C`。

需要注意，程序中的路径大多是相对路径，其实际位置由启动程序时的当前工作目录决定，而不是由 Python 文件所在目录决定。

## 5. CSV 文件处理流程

### 5.1 文件触发条件

程序只处理运行期间新创建的 `.csv` 文件。程序启动前已经存在的文件不会被自动处理。

检测到 CSV 后，程序等待 1 秒再读取，以降低文件仍在写入过程中的概率。

### 5.2 文件名时间规则

程序通过以下表达式获取文件时间：

```python
modified_path.split("_")[-3]
```

因此，文件路径按下划线分割后的倒数第三段必须是 14 位时间：

```text
YYYYMMDDHHMMSS
```

例如：

```text
campaign_20260721103000_xxx_event.csv
```

程序使用的是文件名中的时间，不使用操作系统文件创建时间，也不使用 CSV 中的 `starttime`。

### 5.3 发送时间限制

文件名中的时间必须满足以下条件：

- 星期一至星期五；
- 当天 08:30～17:30；
- 文件日期应与程序处理当天一致，否则无法落在由当天日期构造的起止时间内。

不符合时间条件的文件不会被处理，也不会被移动或删除。

### 5.4 输入数据格式

业务 CSV 使用竖线 `|` 分隔，必须至少包含以下字段：

| 字段 | 说明 |
| --- | --- |
| `event_filter_id` | 营销活动或事件过滤器 ID |
| `msisdn` | 用户手机号 |
| `cell_id` | 基站或区域标识 |

程序只保留上述三个字段，然后按照以下组合去重：

```text
event_filter_id + msisdn
```

同一活动中的同一手机号只发送一次；同一手机号属于不同活动时仍可能收到多条短信。

### 5.5 白名单过滤

程序启动时读取：

```text
whitelist/whitelist.csv
```

并将其中的 `msisdn` 列转换为字符串集合。只有存在于该集合中的用户才会继续处理。

白名单只在程序启动时读取一次，运行期间修改文件不会自动生效，需要重启程序。

如果白名单不存在或为空，程序不会发送短信。

### 5.6 排除名单过滤

如果存在以下文件：

```text
exclusive/exclusive.csv
```

程序会读取其中的 `msisdn` 列并排除相应用户。该文件在每次处理业务 CSV 时重新读取。

过滤顺序为：

```text
输入用户 → 白名单过滤 → 排除名单过滤 → 最终发送用户
```

## 6. 短信模板与多语言处理

### 6.1 统一语言模式

默认配置为：

```python
switch_lan = 0
```

此时程序根据 `event_filter_id` 查找配置节，并读取：

```ini
[event_filter_id]
campaign_message = 短信内容
```

### 6.2 区域语言模式

当配置为：

```python
switch_lan = 1
```

程序会读取：

```text
../dim_local_lan.csv
```

并通过以下字段匹配：

```text
业务数据 cell_id = 语言维表 cgisai
```

匹配成功后使用 `Local_Language` 作为活动配置中的键。匹配不到区域语言时，默认使用 `Amharic`。

配置形式类似：

```ini
[event_filter_id]
English = English message
Amharic = Amharic message
Tigrigna = Tigrigna message
```

### 6.3 配置匹配错误

如果 `event_filter_id` 不存在，或者相应的模板键不存在，程序会把以下数据追加到：

```text
id_error/id_error_list.csv
```

记录字段为：

```text
event_filter_id,msisdn
```

## 7. 短信发送流程

短信工作线程从队列中取出任务后，构造发送参数：

| 参数 | 取值 |
| --- | --- |
| 发送方 | `telebirr` |
| 接收方 | `251` + 原始 `msisdn` |
| 短信内容 | 活动配置中的短信模板 |
| 活动名称 | `event_filter_id` |
| 基站 ID | `cell_id` |

程序只是直接在手机号前追加埃塞俄比亚国家码 `251`，没有判断原始号码是否已经包含国家码。

### 7.1 短信编码与拆分

程序调用：

```python
smpplib.gsm.make_parts(msg)
```

该方法负责：

- 选择短信编码；
- 将长短信拆分为多个分片；
- 返回 `data_coding` 和 `esm_class` 等 SMPP 参数。

每个分片分别调用 SMPP `send_message()` 发送。

### 7.2 状态报告请求

发送时设置：

```python
registered_delivery=True
```

表示请求 SMSC 返回短信状态报告。但是当前程序没有启动 SMPP 接收循环，也没有注册状态报告处理器，因此程序实际上不能确认短信是否最终投递成功。

### 7.3 断线重连

如果发送时发生 `ConnectionError`：

1. 将连接状态标记为断开；
2. 重新连接 SMSC；
3. 每隔 5 秒持续重试，直到连接成功；
4. 重新发送当前短信的全部分片。

## 8. 文件及日志输出

### 8.1 运行日志

程序运行日志保存为：

```text
run.log
```

日志只写入文件，没有配置控制台输出。

### 8.2 短信提交记录

短信发送调用结束后，程序追加写入：

```text
myfile_YYYYMMDD.txt
```

记录格式为：

```text
event_filter_id|提交时间|完整接收号码|cell_id
```

该记录仅表示程序调用了 SMPP 提交接口，不代表 SMSC 已接受，也不代表短信已经送达用户。

### 8.3 原始文件处理

业务数据写入发送队列后，程序会直接删除原始 CSV，不会移动到 `sms_finished`。

## 9. 停止流程

用户按下 `Ctrl+C` 后，程序执行：

1. 向短信队列末尾写入 `None`；
2. 等待发送线程结束；
3. 停止目录监听；
4. 解绑并断开 SMSC。

由于停止标记位于队列末尾，程序会先处理此前已经入队的全部任务。如果发送期间持续无法连接 SMSC，程序可能一直停留在重连流程中。

## 10. 当前样例文件与程序要求的差异

`old_script` 目录当前包含：

- `market_template_marketing_thread.py`；
- `input_event.csv`；
- `whitelist.csv`。

当前样例与程序要求存在以下差异：

1. 程序查找 `whitelist/whitelist.csv`，但当前文件位于 `old_script/whitelist.csv`；
2. 当前白名单使用 `|` 分隔，但脚本读取白名单时没有指定 `sep="|"`，默认会按逗号读取；
3. `input_event.csv` 文件名中不包含脚本要求的 14 位任务时间，文件名时间解析会失败；
4. 当前项目父目录没有发现 `campaign_configuration.ini`；
5. 当前项目父目录没有发现多语言模式需要的 `dim_local_lan.csv`。

因此，当前样例文件不能直接驱动原型脚本完成短信发送流程。

## 11. 已识别的风险和问题

### 11.1 原始 CSV 删除过早

CSV 在短信任务写入内存队列后立即被删除，但此时短信可能尚未发送。如果程序崩溃、服务器重启或工作线程退出，队列中未处理的任务会永久丢失。

### 11.2 长短信可能重复发送

如果长短信的部分分片已经成功发送，后续分片发送时连接中断，重连后程序会重新发送全部分片，可能导致短信重复或拼接异常。

### 11.3 缺少状态报告处理

程序虽然请求了 delivery receipt，但没有接收和解析状态报告，无法区分：

- SMSC 接受；
- 运营商投递成功；
- 用户终端收到；
- 投递失败及失败原因。

### 11.4 工作线程可能静默退出

`sms_worker()` 没有顶层异常处理。除 `ConnectionError` 之外的发送异常、日志文件写入异常或协议异常都可能使工作线程永久退出，而主程序仍会继续把任务放入队列。

### 11.5 异常信息不足

文件处理大量使用：

```python
except Exception as e:
    logging.info(e)
    pass
```

程序只记录异常文本，没有完整堆栈，也没有重试或错误文件隔离机制，不利于排查问题。

### 11.6 子目录文件删除路径错误

监听器会递归监控子目录，读取文件时使用完整路径，但删除文件时只使用文件名：

```python
os.remove(filename)
```

如果业务 CSV 位于子目录，可能出现删除失败，或者误删当前目录下同名文件的问题。

### 11.7 监听范围过宽

程序递归监听当前目录中的所有 CSV，包括白名单、排除名单、错误记录和其他非业务文件。这些文件被创建时也会触发处理，通常只能依赖文件名解析异常来跳过。

### 11.8 敏感配置硬编码

SMSC 地址、端口、账号和密码直接写在源代码中，存在凭据泄露风险，也不利于开发、测试和生产环境切换。已经进入源码的密码应进行轮换，并迁移到环境变量或受控配置中。

### 11.9 相对路径依赖启动目录

配置、名单、日志和输出目录全部使用相对路径。如果从不同目录启动脚本，程序会读取或创建不同位置的文件，容易出现配置缺失和数据散落。

### 11.10 手机号格式未校验

程序直接在号码前添加 `251`，没有执行空值、长度、字符和已有国家码校验，可能生成无效号码或重复国家码。

## 12. 总结

该程序的核心定位是一个基于文件事件触发的单线程 SMPP 营销短信发送器。它已经覆盖任务时间控制、名单筛选、活动模板、多语言、短信拆分、发送队列和断线重连等基础功能。

当前版本属于原型或内部脚本形态，在正式生产化之前，需要重点完善任务持久化、文件生命周期、状态报告、异常恢复、路径管理、号码校验、配置安全和运行监控。
